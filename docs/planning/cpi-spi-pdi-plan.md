# CPI·SPI·개인차 분석 및 서비스 계획

상태: `Accepted` (모델링 명세) · 모델링 명세: `v1` · 작성/수정일: 2026-09-24

이 문서는 실험 구현의 기준으로 확정한다. 명세의 승인은 후보 모델의 성능이나 공개 지표의 타당성이 검증됐다는 의미가 아니다. 아래 Open 항목은 실험으로 결정하며, 학습 결과를 선취하지 않는다.

| 대상 | 상태 |
| --- | --- |
| 모델링 명세 | v1 Accepted |
| 모델 | Candidate, 미학습·미검증 |
| 공개 CPI/SPI 명칭·척도 | Open |
| PDI | Experimental / Candidate |
| 서비스 목표 | Lv48~50, 표본·검증에 따라 하위 레벨 확장 |
| 첫 실험 | Lv49 CPI: Level only → User + Level → User + Level + Chart 비교 |

구현·학습 실행은 아직 시작하지 않았다.

## 핵심 관측 가정과 분석 흐름

**v1은 시간에 따른 변화가 없는 정적 사용자 능력을 가정한다.** Lv48~50에도 과거와 최근의 기록이 섞이며, 최고 기록 기반 능력은 현재 시점의 실력을 정확히 나타낸다고 보장할 수 없다. 이 제한은 하위 레벨에만 해당하지 않는다. 신뢰할 수 있는 실제 플레이 시각을 확보하기 전에는 lastPlayedAt이나 DB 갱신 시각으로 임의의 시간 감쇠 가중치를 만들지 않는다. 향후 시간 모델에는 별도 데이터 계약과 검증이 필요하다.

**관측 단위는 한 번의 플레이가 아니라 보유 기록 상태다.** 한 번 도전해 클리어한 경우와 100번 중 한 번 클리어한 경우가 모두 clear=1로 기록될 수 있다. 시도 횟수·연습량·기록 시점을 분리할 수 없으므로 chartClearDifficulty는 관측된 보유 기록 기준 상대 난이도다. Rasch 형태를 사용하더라도 단일 시도의 성공확률이나 현재 실력의 인과적 측정으로 해석하지 않는다. SPI 역시 최고 점수의 보유 분포를 설명하며 시도별 기대 점수가 아니다.

**관측 채보 선택은 무작위가 아니다.** 사용자는 실력·선호·곡 인지도·해금 상태 등에 따라 채보를 선택한다. 따라서 records의 결측을 MCAR로 가정하지 않으며, 관측되지 않은 성과와 선택 과정이 연관될 수 있는 MNAR 가능성을 고려한다. v1의 사용자 실력과 채보 난이도는 관측된 popn.gg 기록 집단의 상대적 구조를 설명한다. `P(clear | observed)`를 잘 예측해도 모든 사용자가 해당 곡을 플레이했을 때의 결과를 추정했다고 볼 수 없다. 미플레이를 실패나 임의 성적으로 채우지 않고, 전체 플레이어 모집단에 대한 무편향 난이도라고 주장하지 않는다. 사용자 효과를 보정했다는 이유만으로 선택 편향이 제거됐다고 가정하지 않는다.

분석 흐름은 다음과 같다.

```text
원천 기록 → eligibility → user skill / chart difficulty 분리
→ out-of-sample 검증 → 잔차와 순위 지표를 함께 보는 개인차 후보
→ 불확실성 평가 → 서열/파티션 → 공개 여부 결정
```

## 1. 목표와 초기 범위

실제 플레이 보유 기록에서 플레이어의 실력과 채보 난이도를 함께 추정한다. 클리어 능력(CPI 계열), 스코어링 능력(SPI 계열), 평균적인 실력으로 설명되지 않는 개인차 후보(PDI)를 분리한다.

- **초기 서비스 대상은 Lv48·49·50이다.** Lv49만 출시하는 계획이 아니다.
- 실험은 Lv49부터 시작할 수 있지만, 출시 전 Lv48·50도 각각 검증한다.
- 원천 데이터와 기초 통계는 모든 레벨을 계속 수집한다.
- 초기 모델 학습과 모델 간 비교에는 Lv48~50의 적격 기록을 사용한다. Lv47 이하는 기본 학습에서 제외한다.
- 표본과 검증 근거가 충분해지면 Lv47 이하로 서비스 범위를 확장한다. 영구적인 고레벨 전용 지표로 제한하지 않는다.
- 지원 레벨의 표본 부족 채보는 목록에서 삭제하지 않고 **판정보류**로 표시한다.
- 클리어 서열표와 스코어 서열표를 별도로 제공하는 것이 목표다. 투표 기여, 본인 기록 표시, 이미지 내보내기는 후속 화면 기능으로 유지한다.

기존 [레벨별 서열표 계획](level-tier-list-plan.md)의 구 팝클 고정축·고정 등급 방식은 현재 모델의 전제로 사용하지 않는다. 모델과 자동 파티션은 이 문서를 우선하며, 투표·개인화·이미지 저장의 상세 정책은 후속 검토한다.

## 2. 용어와 지표 방향

이전 논의의 CPI/SPI는 플레이어 실력 지표였고, 후속 제안에는 채보 난이도의 의미도 포함됐다. 내부 필드에서는 두 대상을 반드시 구분한다. 약어의 영문 풀네임과 최종 공개 명칭은 미정이다.

| 내부 값 | 의미 | 값이 클수록 |
| --- | --- | --- |
| userClearSkill | 플레이어의 클리어 능력 | 클리어 능력이 높음 |
| chartClearDifficulty | 채보의 클리어 난이도 | 클리어가 어려움 |
| userScoreSkill | 플레이어의 스코어링 능력 | 높은 점수를 내는 능력이 높음 |
| chartScoreDifficulty | 채보의 스코어 난이도 | 높은 점수를 내기 어려움 |
| cpiPdiCandidate | 클리어 개인차 후보 | 같은 레벨에서 설명하기 어려운 정도가 큼 |
| spiPdiCandidate | 스코어 개인차 후보 | 같은 레벨에서 설명하기 어려운 정도가 큼 |

최종 화면에서 채보 난이도를 CPI/SPI로 표시할지는 검증 후 확정한다. 내부 로짓·회귀계수를 곧바로 공개 레이팅으로 부르지 않는다. 48.xx~50.xx 매핑도 현재 확정하지 않는다.

CPI와 SPI를 하나의 실력값으로 합치지 않는다. 두 난이도의 차이는 클리어와 스코어의 특성 차이이며, 그 자체로 개인차곡이라는 뜻은 아니다. 척도가 다른 원시 계수를 직접 빼지 않고 같은 레벨의 순위·백분위로 비교한다.

## 3. 데이터 계약과 현재 구현의 경계

현재 기초 분석기는 records, chart_stats, level_stats, user_stats, user_level_stats, score_percentiles, cpi_readiness, data_quality, report, summary 등의 산출물을 생성한다. **이 결과에는 최종 CPI/SPI/PDI 점수가 없다.**

| 입력 | 용도 |
| --- | --- |
| records.csv / records.jsonl | 유저·채보별 원천 기록 및 eligibility |
| catalog.json | chartId, songId, level 연결 |
| chart_stats.csv | CPI/SPI별 표본·클리어율·점수 분포 |
| score_percentiles.csv | 채보별 점수 ECDF와 동점 분포 |
| cpi_readiness.csv | 모델링 준비도 탐색 자료 |
| data_quality.json / source_metadata.json | 제외 사유·추출 기준·품질 확인 |
| manifest.json | 입력 파일 해시·정책·스냅샷 식별 |

제안된 `song_catalog.csv`는 현재 산출물에 있다고 가정하지 않는다. 모델링 전 동일 스냅샷 기준으로 songId와 곡명·장르·아티스트·버전을 제공하는 카탈로그 추출을 추가해야 한다. 곡명 결합에는 현재 DB를 나중에 조회해 섞지 않고 스냅샷 기준 정보를 사용한다. 결과에는 반드시 곡명과 chartId·songId를 함께 넣는다.

데이터 사용 규칙:

- CPI: `48 <= level <= 50 AND cpiEligible == true`의 유저·채보·레벨·이진 cleared만 사용한다.
- SPI: `48 <= level <= 50 AND spiEligible == true`의 유저·채보·레벨·최고 score만 사용한다.
- 기존 eligibility 정책을 재사용하고, 변경 시 별도 정책 버전과 전후 표본 차이를 남긴다.
- CPI에서 일반 클리어 이상은 모두 같은 성공이다. BAD 구간·FC·PERFECT를 가산점으로 사용하지 않는다.
- SPI에는 클리어 여부나 메달을 직접 넣지 않는다. 적격 FAILED 고득점도 포함한다.
- 미플레이는 FAILED가 아니다. 유저·채보당 기록 하나를 사용하고 중복·비공개·BOT·삭제 채보 처리 정책을 지킨다.
- 최고 점수와 최고 메달이 같은 플레이에서 나온 결과라고 가정하지 않는다.
- history는 전체 시도 이력이 아니며 DB 갱신 시각은 실제 플레이 시각이 아니다.
- 짠게이지, 노트 수, BPM, 패턴, 후살·초살 등의 임의 보정은 추가하지 않는다.

## 4. CPI 후보 모델

초기 기준 모델은 규제된 1PL Rasch 형태다.

```text
P(보유 기록상 clear_ui = 1)
    = sigmoid(userClearSkill_u - chartClearDifficulty_i)

chartClearDifficulty_i = levelDifficulty_level(i) + chartDeviation_i
```

난이도가 높을수록 성공 확률이 낮아지도록 부호를 고정한다. 공식 레벨마다 임의의 기본 CPI를 부여하지 않으며 levelDifficulty는 데이터에서 추정한다. 레벨별 추정값의 단조 증가를 강제할지는 별도 검증 없이 결정하지 않는다.

v1 기준 모델의 식별 제약은 다음으로 고정한다. U는 해당 적합의 학습 사용자 집합, C_L은 해당 적합에서 레벨 L의 채보 집합이다.

```text
mean(userClearSkill_u for u in U) = 0
각 레벨 L에 대해 mean(chartDeviation_i for i in C_L) = 0
chartClearDifficulty_i = levelDifficulty_L + chartDeviation_i
```

평균은 기록 수로 가중하지 않는 사용자별/채보별 산술평균이다. CPI 식에는 별도 자유 절편을 추가하지 않는다. 제약은 최종 출력에서만 맞추지 않고 적합 중에도 제약된 파라미터화/최적화로 강제한다. 정규화된 효과에 규제를 적용하고, 수렴 및 제약 오차를 허용 오차와 함께 검증한다. 학습 집합이 달라지는 fold/bootstrap마다 같은 제약을 적용한다. C_L이 비어 있으면 해당 레벨 효과를 적합하지 않는다. 유저-채보 연결 그래프가 분리된 집단의 계수는 바로 비교하지 않는다. SPI는 후보 모델의 절편·척도에 맞는 식별 제약을 별도로 명시해야 한다.

현재 관측은 시도별 성공률이 아니다. 모델의 확률도 우선 **관측된 보유 기록 집단에서의 클리어 상태 확률**로 해석한다. 개별 다음 플레이의 성공 확률이라고 홍보하지 않는다.

전원 클리어/실패 채보는 규제 추정치와 한쪽 결과 플래그를 보존할 수 있지만, 근거가 약한 값에 확정 순위를 부여하지 않는다. 2PL은 1PL 검증 후 추가 후보로 비교한다.

## 5. SPI 후보 모델

CPI와 별도 사용자 능력을 추정하고 다음 후보를 동일한 분할에서 비교한다.

| 후보 | 모델과 검토 사항 |
| --- | --- |
| 연속 점수 모델 | score = intercept + userScoreSkill - chartScoreDifficulty + error. Ridge 또는 혼합효과 후보. 점수 범위·천장 효과·이상치·오차 분산 확인 |
| 채보 내 ECDF 기반 | 점수를 같은 채보 내 상대 위치로 변환해 능력과의 관계를 탐색. 채보별 절대 점수 난이도 정보를 지우므로 이것만으로 채보 스코어 난이도를 확정하지 않음 |
| 목표 점수 모델 | 90,000·93,000·95,000·98,000·99,000 이상 달성 여부를 공동 모델링. 임계점 순서와 달성 확률의 단조성을 보장하는 ordinal/graded response 후보 |

평가 데이터를 포함해 ECDF를 만들지 않는다. 검증 시 학습 집단의 분포로 변환한다. 동일 사용자·채보에서 만든 여러 목표 점수 라벨은 독립 표본으로 간주하지 않고 같은 분할에 둔다.

SPI 난이도가 목표 점수에 따라 달라질 수 있으므로 필요하면 목표별 난이도를 보존한다. 단일 SPI로 요약하는 규칙은 예측 성능과 해석을 보고 결정한다.

## 6. 개인차 후보와 누출 방지

개인차 후보는 전반적인 실력이 비슷해도 채보별 성과가 다르게 나타나는 현상을 탐색한다. 난이도와 별도로 계산하며, 특정 패턴이나 랜덤성이 원인이라고 단정하지 않는다.

평가 채보의 기록을 그 사용자의 기준 실력 추정에 포함하지 않는다. 채보 ID의 안정적인 해시로 fold를 고정하고, 평가 fold 밖의 채보에서 사용자 실력을 추정하는 cross-fitting을 기본 후보로 한다. fold 수·해시·seed를 모델 설정에 저장한다.

같은 곡의 다른 난이도/UPPER가 평가에 미치는 영향을 확인하고, songId 단위 분할도 민감도 분석한다. 별도로 예측 성능 검증에서는 평가 대상 사용자-채보 라벨이 계수 추정·튜닝·ECDF에 섞이지 않도록 학습/검증/최종 평가를 구분한다. 평가 채보의 난이도·기울기를 따로 맞추는 경우에도 적합 사용자와 평가 사용자를 분리한다.

| 지표 | 탐색 방법 | 주의점 |
| --- | --- | --- |
| CPI 개인차 | 대상 채보를 제외한 사용자 실력과 clear 사이의 AUC | 성공·실패 양쪽 필요. 관측 사용자 실력 범위·선택 편향·실력 추정 오차에 영향받음 |
| SPI 개인차 | 대상 채보를 제외한 사용자 실력과 점수의 Spearman rho | 동점·천장 효과·좁은 사용자 실력 범위 확인 |

한 채보 내 점수를 순서와 동점이 보존되는 ECDF로 바꾸면 Spearman 결과는 동일하다. 변환 자체를 개선 효과로 주장하지 않는다. raw score 및 ECDF는 해석 자료로 함께 보관한다.

낮은 AUC/rho는 개인차의 확정 증거가 아니다. 기준 사용자 실력 분포, 예측 보정도, 잔차, 반복 분할 안정성을 함께 본다. AUC가 0.5보다 낮거나 음의 상관이 나오면 무조건 최고 PDI로 처리하지 않고 데이터·부호·연결성·모델 부적합을 조사한다.

### 개인차 진단 산출물

AUC/rho 외에 아래 값을 **같은 out-of-sample 평가 집합에서 반드시 함께 저장**한다. CPI는 예측 확률 p, 결과 y에 대해 residual = y - p로 정의한다.

| 영역 | 채보별 필수 진단 |
| --- | --- |
| CPI | AUC, Brier score = mean((y-p)^2), log loss, mean(y), mean(p), 잔차 평균·분산, clearCount, failCount |
| SPI 연속 모델 | Spearman rho, residual = observedScore - predictedScore의 평균·분산, MAE, 점수 단위와 변환 정의 |
| SPI 목표 점수 모델 | 목표별 Brier/log loss 및 확률 잔차. 연속 점수를 예측하지 않으면 점수 MAE를 임의 생성하지 않음 |
| 공통 | 평가 사용자 수, 기준 실력 min/max·P10/P50/P90·표준편차, skill-range, 기준 채보 수 분포, 실력대별 observed/predicted·잔차 요약 |

실력 구간의 경계는 학습/검증 단계에서 고정하고 최종 평가에서 재튜닝하지 않는다. 작은 구간은 표본 부족을 표시한다. 확률 log loss의 수치 안정화 규칙도 설정에 저장한다. 확률을 생성하지 않는 순위 전용 기준 모델은 해당 진단을 산출 불가로 표시하며, 이를 완전한 PDI 검증 결과로 취급하지 않는다.

이진 결과의 잔차 분산은 p(1-p)와 평균 클리어율의 영향도 받는다. 원시 잔차 분산이 크다는 이유만으로 개인차라고 판단하지 않고 모델 기대 오차·실력 분포·표본 크기와 함께 비교한다. SPI도 점수 단위·목표별 분포를 구분한다. 높은 상관 속 특정 실력대의 불일치와 낮은 상관을 별도 진단한다.

## 7. 표본, 보류, 신뢰도

**채보별 적격 고유 사용자 50명 이상**을 초기 기본 기준으로 사용한다. 원천 행 수로 대체하지 않는다.

- CPI, SPI, CPI-PDI, SPI-PDI의 적격 사용자 수를 각각 저장한다.
- PDI 표본 수는 cross-fitting에서 기준 실력을 추정할 수 있는 사용자만 센다. 원래 플레이어 수가 50명이어도 PDI 표본은 부족할 수 있다.
- CPI-PDI는 클리어와 실패 양쪽 최소 표본 기준도 필요하다. 숫자는 데이터 분포 확인 후 결정하고 설정으로 관리한다.
- SPI-PDI는 유효 점수의 변동과 충분한 동점 외 순위 정보가 필요하다.
- 사용자별 기준 채보 최소 개수, 신뢰구간 폭 기준, 최소 성공/실패 수는 `Open`이다.

보류 사유는 기계 판독 가능한 값으로 남긴다. 예: INSUFFICIENT_PLAYERS, ONE_SIDED_OUTCOMES, INSUFFICIENT_REFERENCE_CHARTS, CONSTANT_SCORE, DISCONNECTED_COMPONENT, LOW_CONFIDENCE. 값은 제안이며 아직 API 계약이 아니다.

신뢰구간은 사용자 단위 bootstrap으로 여러 채보에 걸친 동일 사용자의 의존성을 보존하는 방식을 우선 검토한다. 최종 추정 불확실성에는 가능하면 모델 재적합을 포함한다. 고정 실력값에 대한 조건부 신뢰구간만 계산했다면 그 한계를 표시한다. bootstrap 횟수와 seed는 버전 관리한다.

## 8. PDI 표시 후보

검증을 통과한 채보들에 한해, 같은 레벨 내 AUC/rho의 역방향 백분위를 0~100 개인차 후보로 표시하는 방안을 검토한다. percentile 전에 불필요한 min-max 정규화를 중복하지 않는다. 동점은 평균 순위 등 고정된 규칙을 적용한다.

- 100은 같은 비교 집단에서 가장 높은 상대 위치이며 절대적인 개인차 크기가 아니다.
- 모든 곡의 관계가 비슷해도 순위 변환은 차이를 강조할 수 있어 원시 지표·신뢰구간도 제공한다.
- 비교 집단, 스냅샷, 모델 버전이 바뀌면 백분위도 달라진다.
- 종합 PDI 평균은 **실험용 후보**다. 두 구성 지표가 모두 유효할 때만 계산한다.
- 한쪽이 보류이면 다른 쪽을 복사하거나 0으로 채우지 않는다. 종합은 null/판정보류로 둔다.

## 9. 검증과 출력

첫 실험은 Lv49에서 디버깅·해석을 시작하되, 이후 Lv48~50 공동 학습과 레벨별 결과를 비교한다. Lv49 전용 모델 계수를 다른 레벨 계수와 그대로 연결하지 않는다.

### 평가 분할

두 평가를 분리하고 각각의 성능·표본·제외 사유를 보고한다. 하나의 점수로 합치지 않는다.

| 분할 | 질문 | v1 평가 절차 |
| --- | --- | --- |
| interaction holdout | 알려진 사용자의 관측 기록 일부를 숨겼을 때 예측 가능한가? | 유저-채보 기록을 분리하되 기준 기록이 남도록 한다. 평가 라벨을 사용자·채보 효과 적합에 넣지 않는다. 기존 사용자 서비스의 주 평가다. |
| user holdout | 학습에 없던 사용자에게 일반화되는가? | 사용자를 통째로 글로벌 모델 적합·튜닝·ECDF에서 제외한다. 평가 시 채보 계수를 고정하고, 새 사용자의 support 채보만으로 능력을 추정한 뒤 분리된 query 채보를 평가한다. |

user holdout에서 자유로운 사용자 효과를 사용자 ID만으로 예측할 수 있다고 가정하지 않는다. support 개수별 성능을 따로 보고하며 query 정답은 능력 추정에 사용하지 않는다. support가 전혀 없는 zero-shot 조건은 개인별 실력 추정 대신 학습 집단 사전분포에 기반한 기준 예측으로 별도 보고한다. 신규 채보 일반화는 이 두 평가와 다르며 현재 검증 완료로 주장하지 않는다.

interaction holdout도 원래 기록이 있는 쌍을 숨기는 평가이므로, 실제 미플레이 곡 전체에 대한 정확도를 증명하지는 않는다. holdout 대상, support/query 배정, 튜닝/최종 평가의 사용자 분리, seed, 평가 누락 비율을 manifest에 저장한다. 개인차용 채보 cross-fitting과 예측 검증 분할의 목적을 구별하며, 필요한 조합에서도 평가 대상 기록이 기준 능력 추정에 들어가지 않도록 한다.

### 기준 모델과 비교 대상

CPI는 다음 세 모델을 같은 관측·평가 집합에서 비교한다. sigma는 sigmoid이며 사용자·레벨·채보 효과의 방향 및 식별 제약은 4절을 따른다.

```text
Baseline A — Level only:
P(clear_ui) = sigma(-levelDifficulty_L)

Baseline B — User + Level:
P(clear_ui) = sigma(userClearSkill_u - levelDifficulty_L)

Candidate — User + Level + Chart:
P(clear_ui) = sigma(userClearSkill_u - levelDifficulty_L - chartDeviation_i)
```

A도 학습 기록으로 레벨 효과를 적합한다. Lv49 단독 실험에서는 A가 규제된 단일 상수 확률 기준 모델이 된다. B에는 채보별 효과가 없고, Candidate만 같은 레벨 내 상대 난이도를 만든다. 전원 성공/실패에서도 무한 계수가 나오지 않도록 기준 모델의 규제 정책도 기록한다.

SPI 연속 점수 후보의 기준은 아래와 같다. mu는 학습 기록에서만 추정한다.

```text
Baseline A — 전체 평균:
predictedScore_ui = mu

Baseline B — User + Level:
predictedScore_ui = mu + userScoreSkill_u - levelDifficulty_L

Candidate — User + Level + Chart:
predictedScore_ui = mu + userScoreSkill_u - levelDifficulty_L - chartDeviation_i
```

SPI에서 절편 mu와 레벨 효과를 함께 쓰면 학습 사용자 평균 실력 0, 학습 레벨 효과의 비가중 평균 0, 레벨 내 채보 편차 평균 0을 적용한다. 목표 점수 모델은 전체 목표 달성률/사용자+레벨/사용자+레벨+채보 순으로 같은 비교 구조를 만들고, ECDF 후보도 목표 변수와 척도에 맞는 기준을 보고한다. 연속 점수 MAE와 ordinal log loss를 직접 비교해 승자를 고르지 않는다. 후보 간 선택에는 validation에서 합의한 공통 예측 과제·지표와 해석 기준을 사용한다.

### 모델 선택과 최종 평가 잠금

```text
train      → 파라미터 적합
validation → 규제 강도·SPI 모델·임계값·파티션 정책 선택
test       → 선택을 끝낸 모델의 최종 성능 1회 보고
```

최종 test를 보기 전에 모델 종류, 전처리, eligibility, 분할, 평가 지표, 불확실성 계산 방식, 선택 규칙과 임계값을 고정하고 설정 해시를 남긴다. test에 대한 SPI 후보 비교로 최종 모델을 선택하지 않는다. 필요하면 미리 정한 절차로 train+validation에 재적합하되 test는 계속 분리한다.

test 결과를 보고 정책을 바꾸면 새 실험 버전으로 기록한다. 이미 본 test를 새로운 독립 평가로 재사용하지 않으며, 새로운 잠금 평가 집합이나 사전에 설계한 nested 검증이 필요하다. bootstrap과 순위 진단도 test를 모델 선택에 사용하는 우회 경로가 되어서는 안 된다.

### 첫 Lv49 CPI 실험의 필수 비교표

validation과 최종 test를 각각 보고하며 표에 평가 분할·고유 사용자 수·기록 수를 명시한다. interaction holdout이 주 평가이며 user holdout은 support 조건별 별도 표로 작성한다.

| Model | Log loss | Brier | AUC | Calibration | Rank stability |
| --- | --- | --- | --- | --- | --- |
| Level only | 미실행 | 미실행 | 미실행 | 미실행 | N/A: 레벨 내 채보 효과 없음 |
| User + Level | 미실행 | 미실행 | 미실행 | 미실행 | N/A: 레벨 내 채보 효과 없음 |
| User + Level + Chart | 미실행 | 미실행 | 미실행 | 미실행 | bootstrap 채보 순위 안정성 |

Calibration에는 평균 예측/관측 클리어율과 고정 구간별 표본·예측·관측을 함께 저장한다. Rank stability에는 같은 적격 채보 집합의 기준 순위 대비 bootstrap 순위 상관, 채보별 순위 구간, 비교 가능한 반복 수를 포함한다. PDI나 최종 공개 척도의 검증 완료로 확대 해석하지 않는다.

Candidate와 B의 log loss/Brier 차이는 같은 평가 표본에서 비교하고 사용자 단위 불확실성을 함께 보고한다. validation 개선과 bootstrap 안정성이 확인되어도 test 평가·보정도·선택 편향 검토까지 통과하기 전에는 공개 난이도로 확정하지 않는다. 개선이 없으면 그 결과를 그대로 보고하고 채보 효과 모델을 억지로 채택하지 않는다. 개선 폭·안정성의 채택 임계값은 test 개봉 전에 validation에서 확정한다.

### 필수 검증

1. 공식 레벨만 사용하는 기준 모델, raw clearRate/medianScore 순위, 사용자 구성 보정 모델을 비교한다.
2. CPI는 평가 log loss, Brier score, 보정도와 AUC를 함께 본다. SPI는 연속 점수 오차 또는 목표별 확률 성능을 모델에 맞게 비교한다.
3. CPI 난이도와 CPI-PDI, SPI 난이도와 SPI-PDI의 관계를 확인한다. 높은 상관만으로 설계 오류라고 단정하지 않고 난이도·표본·성공률·사용자 구성의 영향을 분리한다.
4. 표본이 적거나 클리어율이 극단적이라는 이유만으로 PDI가 커지는지 확인한다.
5. 규제 강도, 분할 seed, 기준 채보 수, 연결 집단, 오래된 기록 포함 여부에 따른 순위 안정성을 확인한다.
6. readiness 증가 경향 및 Lv49 클리어율과 점수의 약한 관계는 아직 검증된 사실로 인용하지 않는다. 선택한 스냅샷에서 직접 재계산한다.

잔차·확률 오차·skill-range·clear/fail counts는 채보별 진단 파일과 실력대별 진단 파일에 저장하고 주 결과의 chartId·평가 분할·modelVersion으로 연결한다.

출력에는 level, songName, chartId, songId, chartClearDifficulty, chartScoreDifficulty, clearRate, medianScore, cpiSampleCount, spiSampleCount, cpiPdiSampleCount, spiPdiSampleCount, cpiAuc, spiSpearman, cpiPdiCandidate, spiPdiCandidate, pdiCandidate, 신뢰구간, 상태와 보류 사유를 포함한다.

클리어 난이도순·스코어 난이도순·각 개인차순·종합 개인차순을 별도로 저장한다. raw 순위, 보정 순위, 순위 변화량을 함께 출력한다. 보류된 채보는 억지로 순위를 채우지 않는다.

## 10. 서열표와 자동 파티션

하/중/상처럼 고정된 구간 개수를 강제하지 않는다. 검증된 난이도 축에서 차이가 뚜렷한 위치를 찾아 자동 분할하는 것이 목표다. CPI와 SPI 경계는 독립적으로 계산한다.

v1 파티션 후보는 단순한 인접 난이도 절대차만으로 선택하지 않는다. 같은 bootstrap 재적합에서 나온 두 채보의 난이도 쌍을 사용한다.

```text
delta_b = difficulty_(i+1,b) - difficulty_(i,b)
orderStability = mean(delta_b > 0)
gapSupport(epsilon) = mean(delta_b > epsilon)
```

기준 적합에서 정한 인접 순서를 고정한 뒤 bootstrap별 차이를 계산한다. 매 반복에서 다시 정렬한 뒤 비교하면 순서 유지율이 자명해지므로 금지한다. 동일 반복의 추정치 쌍으로 공분산을 보존하고, 두 채보가 비교 가능한 연결 집단에서 적합된 유효 반복 수와 실패 비율도 저장한다.

orderStability는 bootstrap 순서 유지 비율이며 별도 가정 없이 Bayesian posterior probability로 부르지 않는다. 인접 채보 각각의 주변 신뢰구간 겹침만으로 판단하지 않고 **차이 delta의 신뢰구간**과 함께 본다. 순서가 안정적이어도 차이가 매우 작으면 서비스 구간 분리를 정당화하지 못하므로, 실질적인 차이 epsilon과 최소 구간 크기도 필요하다. 여러 후보 경계의 우연한 선택 및 전체 분할 안정성을 검증한다.

최소 순서 유지율, epsilon, 최소 구간 크기, bootstrap 경계 안정성, 일별 경계 변경 억제 정책은 검증 데이터로 후속 결정하며 설정으로 버전 관리한다. 분리 근거가 없으면 한 구간으로 남길 수 있다. 불확실한 인접 순위 차이를 경계로 과장하지 않는다. 개인차와 판정보류는 난이도 축의 최상위 구간으로 취급하지 않는다.

투표 결과는 모델 추정과 별도로 보존하고, 초기 학습 정답으로 자동 혼합하지 않는다. 본인 기록을 겹쳐 표시하거나 이미지를 생성할 때는 공개 스냅샷과 기록 기준일을 고정한다.

## 11. S3·실행·결과 전달

현재 기초 통계의 매일 06:00 Asia/Seoul 및 Discord 비동기 실행 구조를 활용한다. 모델 계산도 같은 주기로 공개할지는 실행 시간·비용·안정성 검증 후 결정한다. 원천 수집, 전처리, 모델 적합, 평가, 보고서 생성 코드는 분리한다.

동일 snapshotId, 입력 해시, modelVersion, config, seed에서 같은 결과가 재현되어야 한다. 라이브러리 버전과 계산 환경, 수렴 여부, 제외 내역도 저장한다. 기초 통계와 모델 결과의 latest 포인터를 구분하고, 모든 산출물 및 manifest 검증이 끝난 뒤에만 전환한다. 실패하면 직전 성공 결과를 유지한다.

제안 결과물: chart_model_results.csv, user_model_results.csv(관리자 전용), model_metrics.json, rank_comparison.csv, model_report.md. 현행 통계 파일을 덮어쓰지 않는다.

Discord는 즉시 접수 응답을 반환하고 완료 후 admin bot으로 결과를 알린다. 현재 analysis-result.json은 상태와 S3 위치 중심이므로, 사람이 볼 요약·레벨/채보 CSV·보고서 첨부 또는 만료 링크 제공을 후속 구현한다. 사용자별 원천 기록과 실력 추정값은 공개 첨부에 포함하지 않는다.

## 12. 하위 레벨 확대와 출시 조건

Lv47 이하 확대는 기록 수 증가만으로 자동 결정하지 않는다. 아래 조건을 레벨별로 점검한다.

- 50명 기준을 만족하는 채보의 비율과 부족 채보 규모
- 충분한 성공·실패 및 점수 변동
- 기존 지원 레벨과 연결되는 공통 플레이 사용자·채보
- 예측 성능, 신뢰구간, 순위와 파티션의 안정성
- 오래된 저레벨 기록이 현재 능력을 과소평가하는 영향

확대 시 학습 모집단 변경이 기존 Lv48~50 값에 주는 영향을 비교하고 새 모델 버전으로 배포한다. 기존 스냅샷을 보존하며 과거 수치를 조용히 덮어쓰지 않는다.

출시 전 완료 조건은 Lv48~50별 표본·성능 보고서, 신뢰도/보류 처리, 재현성, S3 실패 복구, 관리자 결과 열람, 사용자/채보 지표의 명칭과 척도 합의다. 데이터가 부족하면 해당 채보를 보류하고, 지표 자체가 검증되지 않으면 해당 지표 공개를 미룬다.

## 13. 구현 순서와 미정 사항

1. 입력 스냅샷·eligibility·곡명 카탈로그를 점검하고 결합한다.
2. Lv49에서 CPI 기준 모델과 SPI 후보를 비교한다.
3. 평가 대상 제외 방식으로 개인차 후보와 불확실성을 계산한다.
4. Lv48~50 공동 모델 및 레벨별 안정성을 검증한다.
5. 자동 파티션과 관리자 보고서를 만든다.
6. 공개 지표·API·화면·본인 기록·이미지 저장을 연결한다.
7. 투표 기여와 하위 레벨 확장을 별도 검증해 추가한다.

미정 사항: CPI/SPI 공개 명칭과 환산 척도, 최종 SPI 모델, PDI 종합 방식, 최소 성공/실패·기준 채보 수, 신뢰구간과 파티션 임계값, 모델 계산 주기·시간 예산, 하위 레벨별 확대 시점. 이 항목들은 구현 편의를 위해 임의 확정하지 않고 실제 결과와 함께 결정한다.
